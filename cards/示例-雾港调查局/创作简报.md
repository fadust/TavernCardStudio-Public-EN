# 角色卡创作简报：雾港调查局

## 体验

- 用户扮演：新入册的雾港调查局调查员，权限从见习开始。
- 主要玩法：接委托、跑现场、记线索、核物证、写结论；搭档共同出勤。
- 开场处境：第一条消息是报到当天的第一份委托（WG-07 搬运工失踪）；三个备选开场白分别是灯塔停灯、鱼市账目、船坞工期。
- 语气与视角：第三人称，客观叙述，一轮推进一段连续调查；不替玩家决定言行。
- 明确排除：超自然解释、东方修真名词、替玩家写台词。

## 角色与世界

- 主要角色：记录官黛莉亚·克雷恩（卡角色），与调查员搭档出勤；配角有局长莫兰·维斯、验尸官奥托·兰姆、码头掮客海蒂、灯塔值守人佩里·道恩。
- 世界规则常驻：雾港三机构分工、雾季与雾况、潮汐、调查局无拘押权、事实与推测分记。
- 按关键词触发：北堤灯塔、潮汐巷鱼市、旧船坞、调查局本部、四位配角、灯塔停灯排查、雾季失踪案办理、港上通用说法。
- 状态：委托编号/名称/阶段、雾港时段/天气/雾况、线索、人物、物证、调查员精力/权限/声望，以及只读的 `_进展`。

## 功能选择

- 纯文字不够：需要跨轮保持委托进度与线索状态，因此用 MVU 变量。
- 状态展示：Vue 状态栏读当前楼层变量，自包含、无外链。
- 正则：隐藏变量更新块与开场初始变量；渲染 `<CardStatus/>` 占位。
- 脚本：两个只读按钮，读取当前委托与雾况摘要。
- 依赖：MVU 框架与 Zod 注册器两条公开外链，固定提交，登记在 `project.json`。

## 交付与验证

- 成品名称：示例-雾港调查局；没有头像，用 JSON 导入。
- 完成标准：`pnpm card check` 无错误、`pnpm card build` 产出到 `dist/示例-雾港调查局/`。
- 验证边界：只做静态检查与本地构建；真实酒馆与模型的注入顺序、渲染、变量更新未验证，`runtimeVerified` 保持 `null`。
