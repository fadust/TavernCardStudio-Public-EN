# 创作说明

本文件不打包、不会发送给模型，只写给维护这张示例卡的人。

## 这张卡是什么

雾港调查局是公开工作区的综合示例卡：卡名是机构名，玩家扮演新入册的调查员，与记录官搭档按委托开展调查，读现场、记线索、核物证、结案。它把世界书、正则、助手脚本、MVU 变量与 Vue 状态栏串成一条完整链路，用来演示各模块怎么配合，而不是只给一份骨架。

- 卡内文本：一条第一条消息 + 三条备选开场白（灯塔停灯、鱼市账目、船坞工期）。
- 世界书：蓝灯的世界观、地理总览、调查局规程、搭档档案与角色总览；绿灯的地点、人物、事件与行话；MVU 四条协议条目。
- 变量：MVU + Zod 注册，字段见 `src/schema.ts`；初始值在 `[initvar]` 条目里，三个备选开场白各自用 `<initvar>` 块覆盖初始值。
- 正则：模板原有的变量更新块四条（显示折叠、提示词屏蔽、完整块与流式各一），加两条处理开场 `<initvar>` 块的，加两条状态栏占位（显示渲染、提示词清除）。
- 界面：`src/ui/vue/` 的迷雾色状态栏，读当前楼层的 `stat_data`，展示委托、时段与天气、雾况、线索、人物、物证与调查员信息。
- 助手脚本：`src/scripts/001-雾港调查局按钮.js` 提供「查看当前委托」「简报雾况」两个只读按钮。

## 世界书布局

按仓库的新卡默认布局排：世界观与地理总览蓝灯、在角色定义之前，具体地点绿灯；搭档档案与角色总览蓝灯，具体人物绿灯，都在角色定义之后；调查局规程属于规则类，放指定深度。

- 蓝灯只放缺失就会破坏体验的内容。世界观交代三个机构的分工、雾季与雾况、潮汐；调查局规程交代委托阶段、线索状态、权限与登记口径，供变量更新规则引用。
- 地理总览只给范围、片区与别称；地点条目写各自的内部细节，不在总览里预加载。
- 角色总览只给身份与分工；说话方式与具体要求写在各人条目里。
- 事件与行话留在角色定义之前：它们是世界设定，不是人物。
- 全部条目两个递归开关都关闭；需要一起出现的设定写进同一条，或靠关键词组合，不靠正文触发另一条。
- 叙事人称、称呼、句长与节奏由酒馆预设负责，卡内条目不重复写一遍。

## 关键词与扫描文本

- `019-事件-雾季失踪案的办理` 演示关键词组合：主关键词收「失踪」「报案」，次要关键词收范围名「雾季」「港区」，逻辑用「任一匹配」，只在主关键词与任一范围名同时命中时注入。
- `018-事件-灯塔停灯的排查` 演示 `/表达式/` 形式的正则关键词；字段 `关键词使用正则` 单独开启并不能保证宿主按正则匹配。
- 关键词只匹配本轮的扫描文本：聊天消息、条目显式勾选的角色描述、允许扫描的扩展注入与递归缓冲。当前地点存在变量里不会自己激活地点条目；要让地点参与命中，需要脚本在扫描前把地点写进聊天消息或允许扫描的注入位置，本卡没有做这件事。

## 变量与提示词的对齐

`src/schema.ts` 是结构真源：`src/variables/schema.json` 只是它的参考投影，不参与运行时校验。同一批字段名与取值出现在五个地方，改动时五处一起改：

1. `src/schema.ts` 的字段与默认值；
2. `src/worldbook/006-[initvar]变量初始化勿开.md` 的初始值，以及三个开场白里的 `<initvar>` 块；
3. `src/worldbook/008-[mvu_update]变量更新规则.md` 的更新条件；
4. `src/worldbook/007-变量列表.md`（固定宏模板，正常不改）；
5. `src/ui/vue/App.vue` 的读取路径。

`调查局._进展` 是只读派生值：由 `线索` 的状态在 Schema 的 transform 里重算，模型不为它写更新规则，脚本与界面也不写它。枚举取值（线索状态三种、人物立场六种、委托阶段五种、调查员权限三档）在 `003-调查局规程.md`、更新规则与界面之间保持一致。

## 状态栏占位

- MVU 在处理助手消息后自己补 `<StatusPlaceHolderImpl/>`，卡内不再要求模型输出占位符，也没有「状态栏输出位置」条目。
- `007-内嵌状态栏`（仅显示）把这个标记渲染成 Vue 界面；`008-屏蔽状态栏占位（仅提示词）` 只从提示词里去掉它，不改动消息本身。
- 开场白不再自带占位符；开场楼层是否出现状态栏，取决于 MVU 是否处理该楼层。

## 演示点

- **蓝灯与绿灯**：世界观、地理总览、调查局规程、搭档档案、角色总览常驻；地点、人物、事件、行话按关键词触发。
- **关键词组合**：`019-事件-雾季失踪案的办理` 用主关键词加范围名，逻辑「任一匹配」，见上文。
- **缺失值处理**：界面对缺字段显示「未记录」并给出空列表提示，不写回默认值；脚本在变量未初始化时给出可执行提示。
- **多开场**：开场白里的 `<initvar>` 块由 MVU 在 0 层读取，覆盖世界书初始值；两条正则分别把它从显示与提示词里去掉。
- **生命周期**：脚本在 `$()` 里注册按钮与监听，在 `pagehide` 里停止监听；按钮名固定，重复加载不会越点越多。

## 未做验证与可扩展方向

- 本卡的验证边界是静态检查与本地构建；没有在真实酒馆里跑过，`project.json` 的 `runtimeVerified` 保持 `null`。
- 需要真实宿主才能确认的：世界书实际注入顺序与命中、流式显示折叠、`<StatusPlaceHolderImpl/>` 的追加时机与渲染、MVU 初始化与重生成后的变量、按钮事件。
- 想加 EJS：本卡没有启用 Prompt Template。要按变量拼提示词时，可在世界书条目或卡字段里写 `<% %>`，并让使用者安装 Prompt Template；注意它在「生成」与「渲染」两个阶段都可能执行，用 `runType` 区分。
- 想让按钮写入状态：走 `Mvu.replaceMvuData(data, { type: 'message', message_id })` 或更新事件，并保留整张变量表；直接写变量不会经过注册器的补全与校验。
