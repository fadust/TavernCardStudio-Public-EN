# 地点扫描与树状设定（按需）

仅在创作者需要按当前地点稳定加载设定时读取。普通卡先用聊天关键词；不要自动给每张卡添加地点脚本。

## 两个独立设计

**树状内容组织**：世界/区域/城镇/地点按范围划分，父条目的关键词可包含下级地名，让同一段扫描文本同时命中父、子条目，再用相同注入位置中的不同顺序排列。主关键词是 OR；需要上级范围消歧时再加次关键词 `任一匹配`。这些是同一轮独立命中，不依靠父条目正文触发子条目，因此双向递归仍可关闭。

例如创作一棵“北境 → 雾岭 → 灰渡口/雾岭镇”的树：

| 层级 | 主关键词 | 次关键词（任一） | 同区块顺序 |
| --- | --- | --- | --- |
| 雾岭总述 | 雾岭、灰渡口、雾岭镇 | 无 | 200 |
| 雾岭地理专题 | 地理、气候、商道、灰渡口、雾岭镇 | 雾岭 | 210 |
| 灰渡口细节 | 灰渡口 | 雾岭 | 220 |

扫描文本为“雾岭 / 灰渡口”时三条可同时命中；只有“灰渡口”时只有无需范围词的总述匹配；只有“雾岭”时不自动加载全部子地点。这个差异是范围条件的结果，不能靠蓝灯总览里出现了“雾岭”补足，因为默认不进行递归触发。角色、事件也可用同样的范围限定；最近聊天中仍有旧地点词时，多地点同时激活是可能的。

各条正文优先自包含。若要把多条拼成 YAML 子树或 XML 包裹块，必须核对共同激活条件、位置、顺序、缩进与预算截断后的可读性；父条目没到达时，子条目不能变成无法识别归属的残片。目录树本身不赋予运行时树结构。

**把状态加入扫描**：脚本读取本卡真实地点路径，在当前请求的世界书扫描前提供地点/上级范围词。它不会因为变量名叫“地点”就自动发生，界面显示与变量列表宏也不是扫描保证。

## 酒馆助手接口片段

本地锁定 `references/upstream/tavern-helper/@types/function/inject.d.ts` 提供 `injectPrompts`。`position: 'none'` 不把注入段发送给模型，`should_scan: true` 允许其参与世界书扫描；`once` 控制是否仅下一次生成有效。下面是接入片段，真实脚本还需选择事件、读取路径和清理时机：

```js
const location = '雾岭 / 灰渡口'; // 替换为本卡已初始化状态中的地点路径
const { uninject } = injectPrompts([{
  id: 'card-location-scan',
  position: 'none',
  depth: 0,
  role: 'system',
  content: location,
  should_scan: true,
}], { once: true });
// 取消/卸载或本次生成不再需要时调用 uninject()。
```

MVU 消费者先等 `waitGlobalInitialized('Mvu')`，读取当前聊天中正确楼层的 `stat_data`，不要硬编码其它卡的路径。地点缺失则不注入；只有城市名时不凭空补下级地点。需要范围词的树应从明确的地点索引得到完整路径和别名。

## 接入前必须核对的边界

- 注入仅对当前聊天有效。锁定接口说明给出 `CHAT_CHANGED`、`GENERATION_AFTER_COMMANDS` 两类接入时机；所选事件是否在目标请求扫描前触发、异步读取是否等待完成，仍须按宿主实现确认。
- 清理上一次注入，避免切聊天、重生成、swipe 或移动后残留旧地点。异步等待期间聊天改变时，放弃旧请求的结果。
- 主正文请求与额外变量请求可能走不同生成入口；决定哪边需要地点扫描，不能假设一次性注入自动覆盖两边，非阻塞并发更要隔离请求归属。
- 这里只增加扫描材料，不排除聊天历史中的旧地点词，也不保证预算和其它触发条件允许条目进入。需要严格只激活当前位置时另设计扫描深度、范围关键词或经过核对的激活策略。
- 不为触发世界书而把机械地点串永久写进聊天正文。先验证临时扫描注入方案；生成失败/取消时也要清理。

验收查看实际激活条目和最终提示词：初始地点、跨区域移动、历史旧地点、未知地点、重生成、切聊天、额外请求都要覆盖。没有宿主验证，不宣称脚本已经实现可靠的地点驱动激活。
